# ProCcompile.sh マニュアル

## 目的

提出された C ソースを一括コンパイルし、Windows 用の実行ファイルを作成する。WSL（Debian）の `x86_64-w64-mingw32-gcc` を使う。

このマニュアルは、文字コード変換と `execall.sh` の生成を削除し、コンパイラの出力を `compile.log` に記録する版を対象とする。

## 必要な環境

- WSL（Debian）と Bash。
- MinGW-w64 のクロスコンパイラ。

```bash
sudo apt install gcc-mingw-w64-x86-64
x86_64-w64-mingw32-gcc --version
```

Windows 側の Visual Studio や MinGW-w64 のインストールは、このコンパイル処理には不要。`nkf` も不要。

## 実行方法

```bash
bash ~/wslbin/ProCcompile.sh 提出物フォルダ
```

必須引数は、C ソースが入ったフォルダ１つ。相対パスは、スクリプトの置き場所ではなく、コマンドを実行したカレントディレクトリを基準に解釈する。

例えば、課題ごとの作業フォルダに移動して実行する。

```bash
cd ~/reports/week1
bash ~/wslbin/ProCcompile.sh C提出物
```

フォルダ名に空白がある場合は引用符で囲む。

```bash
bash ~/wslbin/ProCcompile.sh "C 提出物"
```

## 入力ファイル

- 指定フォルダ直下の `*.c` を対象とする。サブフォルダは検索しない。
- 各提出物は、単独でコンパイルできる１つの C ソースを想定する。複数ソースや別途必要なヘッダーを自動でまとめる機能はない。
- UTF-8 のソースを想定する。文字コード・BOM・改行は変換せず、そのままコピーする。
- UTF-8・BOM なし・CRLF の提出物も扱える。
- 元の提出物は変更しない。

コピー先の名前には、拡張子を除いたファイル名の最初の `_` より前の部分を使う。

| 提出ファイル名 | コピー先 | 実行ファイル |
| --- | --- | --- |
| `us227083_氏名.c` | `build/us227083.c` | `build/us227083.exe` |
| `S227083_us227083_01_week1report.c` | `build/S227083.c` | `build/S227083.exe` |

同じ名前に短縮される提出物が複数ある場合は、上書きを避けるため停止する。

## 出力

| 出力 | 保存先・内容 |
| --- | --- |
| コピーした `.c` | カレントディレクトリの `build/` |
| Windows 用 `.exe` | カレントディレクトリの `build/` |
| `compile.log` | カレントディレクトリ。提出物名と、コンパイラの標準出力・標準エラー |

コンパイラの出力は、画面にも表示する。処理開始時に `compile.log` を空にするため、ログは毎回上書きされる。ログ保存の初期化より前に引数・環境チェックで停止した場合は、前回のログが残る。

既存の同名のコピーと実行ファイルは更新する。コンパイル前に同名の `.exe` を削除するため、失敗した提出物について前回の実行ファイルを残さない。ただし、今回の提出フォルダにない学生の古い生成物までは削除しない。課題ごとに作業フォルダを分けると混在を避けられる。

`execall.sh` は生成しない。以前生成したものが残っている場合も更新されない。

## コンパイル設定

スクリプト内の次の配列で設定する。

```bash
CFLAGS=(-Wall -Wextra)
LDLIBS=(-lm)
```

`-std` は指定していないため、C 言語の方言はインストールしたコンパイラの既定値による。授業で明示した指定がある場合は、`CFLAGS` に加える。

## エラーと終了コード

１件がコンパイルに失敗しても、残りの提出物の処理を続ける。最後に成功数と失敗数を画面表示する。

| 終了コード | 意味 |
| --- | --- |
| `0` | 全件成功 |
| `1` | コピーまたはコンパイルに失敗した提出物がある |
| `2` | 引数、必要コマンド、提出フォルダ、ファイル名の重複などに問題がある |

ログ記録のための `tee` を使っても、`set -euo pipefail` によりコンパイラの失敗を検出する。予期しないファイル操作の失敗では、途中停止する場合がある。

## 実行結果の確認

標準入力を使う課題は、同じカレントディレクトリで `input.txt` を用意し、次を実行する。

```bash
bash ~/wslbin/ProCexecStdin.sh
```

詳細は [ProCexecStdin.md](ProCexecStdin.md) を参照。生成した `.exe` は Windows 用であり、WSL から実行するには Windows との連携が有効である必要がある。学生側のコンパイラと版・ライブラリまで同一であることは保証しない。
