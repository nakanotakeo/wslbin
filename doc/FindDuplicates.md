# FindDuplicates.py

## 目的と比較対象

二つのディレクトリを指定し、それぞれの `build/` 直下にある C ソースを一つのプールにまとめ、空白・改行・コメントの違いを無視した一致を調べます。学生の提出物の重複確認を補助するためのスクリプトです。

```bash
python3 FindDuplicates.py dirA dirB
```

| 指定・動作 | 内容 |
| --- | --- |
| 第1引数 | `dirA`。第1の `build/` の親ディレクトリ |
| 第2引数 | `dirB`。第2の `build/` の親ディレクトリ |
| 比較元 | `dirA/build/*.c` |
| 比較先 | `dirB/build/*.c` |
| 検索範囲 | 各 `build/` の直下だけ。サブディレクトリは検索しない |
| 比較単位 | 両側をまとめたプール内の全ファイル。同じディレクトリ内も比較する。ファイル名は一致条件に含めない |

拡張子は小文字の `.c` だけを対象にし、`.C`、`.cpp` などは含めません。`.c` ファイルへのシンボリックリンクはリンク先を読み込みます。A 内だけ、B 内だけ、A と B にまたがる重複をすべて検出します。一つのファイルは一つのグループだけに所属し、2ファイル以上が一致するグループを表示します。同じ `build/` を指す二つの引数はエラーにします。

## 必要なもの

Python 3.8 以降だけで動作します。追加パッケージは不要です。

正規化処理を内蔵しているので、**`FindDuplicates.py` 単独で使用でき、`ProCtokens.py` は不要です。** 元ソースをコンパイル・実行したり、書き換えたりはしません。中間ファイルも作成しません。

## 基本的な使用例

WSL / Debian の例です。

```bash
python3 FindDuplicates.py ProgC2c1_02 ProgC2c2_02
```

例えば、次のように出力します。

```text
一致 3:
   1: ProgC2c1_02/build/foo.c
   2: ProgC2c1_02/build/bar.c
   3: ProgC2c2_02/build/bar.c

一致 2:
   1: ProgC2c2_02/build/answer1.c
   2: ProgC2c2_02/build/answer2.c

比較対象: 計 58 ファイル（A 30 / B 28）
一致: 2 グループ / 5 ファイル
```

`一致 3:` の `3` はグループ内のファイル数です。グループの通し番号ではありません。`1:`、`2:`、`3:` はそのグループ内のメンバー番号です。通常のパスは引用符なしで表示し、タブ・改行を含む特殊なパスだけは JSON の引用表記で表示します。

一致がなければ `一致: 0 グループ / 0 ファイル` と表示します。

同じ正規化結果のファイルが A に2個、B に3個ある場合は、**5ファイルを含む一つのグループ**として表示します。全ペアを繰り返し列挙することはありません。

表示順は、A のファイル名順、次に B のファイル名順に読み込んだ順序です。グループの順序は各グループの最初のメンバーが現れる順序です。

パスに空白を含む場合は、引用符で囲みます。

```bash
python3 FindDuplicates.py "class A" "class B"
```

`build/` 自体ではなく、その親を指定してください。

### 結果をテキストに保存する

```bash
python3 FindDuplicates.py dirA dirB > duplicates.txt
```

警告・個別ファイルの解析エラーは標準エラー出力に出します。通常モードの一致グループと集計は標準出力です。警告も含めて一つのファイルに保存する場合は、次のようにします。

```bash
python3 FindDuplicates.py dirA dirB > duplicates.txt 2>&1
```

### 表形式で保存する

```bash
python3 FindDuplicates.py --tsv dirA dirB > duplicates.tsv
```

`--tsv` では、次の4列を出力します。一つのファイルにつき1行です。

| 列 | 内容 |
| --- | --- |
| `group_id` | グループの通し番号（1から） |
| `group_size` | グループ内のファイル数 |
| `member_index` | グループ内のメンバー番号（1から） |
| `file` | ファイルのパス |

同じ `group_id` の行が同じ一致グループです。先頭行は列名です。一致がなければ列名だけになります。集計・警告・エラーは標準エラー出力に分離します。

ファイル名にタブ・改行・引用符が含まれる場合は、CSV と同じ引用規則で保護します。そうしたファイル名の TSV は、単純な行分割ではなく、Python の `csv.reader(..., delimiter='\t')` などで読み込んでください。

### 入力文字コード

既定値は `utf-8-sig` です。UTF-8 の BOM あり・なしを読み込めます。

CP932 の提出ソースなら次のように指定します。

```bash
python3 FindDuplicates.py --encoding cp932 dirA dirB
```

文字コードの指定は両側共通です。自動推定や解読できない文字の置換は行いません。複数の文字コードが混在する場合は、あらかじめ入力を統一してください。

Windows で Python ランチャーを使用する場合は、`python3` の代わりに `py -3` を使用できます。

## 何を「一致」とするか

ソースをトークン（識別子、数値、演算子、文字列など）に分解し、比較用のデータに正規化します。各ファイルについて一度だけ正規化し、SHA-256 と正規化データ自体の両方をグループ化のキーにして一致を確定します。ハッシュだけの一致で判定することはありません。

| 要素 | 扱い |
| --- | --- |
| 通常のコード中の空白・タブ・改行 | トークンを認識してから除外 |
| コメント | 文字列・文字定数・直接指定ヘッダ名の外側で除去 |
| 文字列・文字定数 | 内部の空白やコメントに見える文字を含め、そのまま保持 |
| 識別子 | 変数名・関数名などの綴りを保持 |
| 数値 | 表記を保持。`1`、`1.0`、`0x1` は区別 |
| 演算子 | 最長一致で分割。`++` と `+ +` などを区別 |
| 改行コード | CRLF / CR / LF を LF に統一 |
| バックスラッシュ直後の改行 | コメントを認識する前に除去して論理行を作成 |
| プリプロセッサ指令 | 論理行の境界を保持 |
| `#define` | 関数形式とオブジェクト形式を区別 |
| 直接指定の `#include` ヘッダ名 | ヘッダ名の内容を保持 |

例えば、次の二つは一致します。

```c
int x = 1;  // 説明
```

```c
int
x=1;
```

次も一致します。

```c
int/**/x = 1;
```

一方、次は不一致になります。

| ソース A | ソース B | 理由 |
| --- | --- | --- |
| `a + +b;` | `a++b;` | 演算子の区切りが異なる |
| `puts("a b");` | `puts("a  b");` | 文字列内部の空白が異なる |
| `puts("a/*b*/c");` | `puts("ac");` | 文字列内部はコメントとして除去しない |
| `int x;` | `int y;` | 識別子が異なる |
| `return 1;` | `return 0x1;` | 数値の表記が異なる |
| `#define F(x) x` | `#define F (x) x` | マクロの種類が異なる |

## 空ファイル・解析エラー

空ファイルや、空白・コメントしかないファイルは一致候補から除外し、その旨を標準エラー出力に表示します。これらをコピペ候補として大量に列挙しないためです。プリプロセッサ指令だけのファイルは空扱いにせず、通常どおり比較します。

個別ファイルの読込み・文字コード解読・字句解析に失敗した場合、そのファイルを除外して残りを比較します。ただし終了ステータスを `1` にし、結果が解析成功分だけであることを集計に明示します。エラーを「一致なし」と読み替えないでください。

`build/` が存在するが `.c` ファイルが一つもない場合は、注意を表示して0ファイルとして処理します。空・コメントのみの除外や0ファイルの注意だけでは失敗扱いにしません。

| 終了ステータス | 意味 |
| --- | --- |
| `0` | 比較を完了。一致の有無には依存しない |
| `1` | 個別ファイルに解析失敗あり。表示結果は成功分のみ |
| `2` | 引数、文字コード名、比較ディレクトリの指定・列挙などのエラー |

## 判定の限界

このスクリプトは、一般的な C99 / C11 の授業課題を主な対象とする簡易字句解析器です。完全な C コンパイラや意味解析器ではありません。

- ファイル全体の正規化結果を比較します。部分的なコピペ、変数名の変更、文の並べ替え、解法の類似度は検出しません。
- `#include` の展開、マクロ展開、`#if` の分岐選択は行いません。`#if 0` の内部も比較対象です。
- マクロの文字列化 `#` では引数内部の空白が動作に影響することがあります。例えば `STR(a+b)` と `STR(a + b)` は、定義が `#define STR(x) #x` の場合に異なる文字列になりますが、本スクリプトでは一致します。`__LINE__` など行番号に依存する動作の同一性も保証しません。
- 文字列・文字定数のエスケープや数値の同義表記は統一しません。
- Unicode 識別子と `\uXXXX` / `\UXXXXXXXX` 表記は字句的に扱いますが、同義表記を統一しません。
- ダイグラフは扱いますが、`<:` と `[` のような同義表記は統一しません。
- トライグラフに見える並び（`??=` など）は、コメント・文字列内も含めエラーにします。C23 やコンパイラ拡張の記法への対応は保証しません。
- 未終了のコメント・リテラル・直接指定ヘッダ名などはエラーにしますが、一般の構文エラーや型エラーを検査するものではありません。エラーの論理行番号は、継続行を結合した後の番号です。

一致する短い課題や配布雛形は、独立に作成しても同じ記述になることがあります。一致グループを確認の入口にし、実際のコピペの判断は元ソースや課題の条件と照合してください。
