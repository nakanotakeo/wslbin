# ProCtokenize.py マニュアル

## 目的

学生が提出した C ソースについて、コメントや空白・改行の配置の違いを無視して、一致する提出物を見つけるための補助スクリプトです。ソースをトークン（識別子、数値、演算子、文字列など）に分解し、比較用の JSON または SHA-256 を標準出力に出します。

出力は C ソースではありません。コンパイルや実行には使いません。また、一致はこのスクリプトの規則でトークン列が一致したことを表し、プログラムの意味の同一性や、コピペの事実を証明するものではありません。

従来の `ProCstripSrc.py` とは別名のスクリプトにしました。従来版の比較結果とは互換性がないので、切り替えるときは比較対象の全ファイルについて出力を作り直してください。

## 動作環境

- Python 3.8 以降。Python 標準ライブラリのみを使用します。
- Debian / WSL では `python3`、Windows では必要に応じて `py -3` で起動してください。
- C99 / C11 の一般的な授業課題の記法を主な対象とする簡易字句解析器です。完全な C コンパイラではありません。

## 基本的な使い方

### 比較用 JSON を出す

```bash
python3 ProCtokenize.py S247001.c
```

例えば、次のソースは、

```c
int main(void)
{
    /* 終了する */
    return 0;
}
```

次のようになります。出力の末尾には改行が付きます。

```json
{"format":"ProCtokens-v1","items":["int","main","(","void",")","{","return","0",";","}"]}
```

JSON 内の文字列は区切りを持つため、トークンを誤って結合しません。例えば `a + +b` は `"a","+","+","b"`、`a++b` は `"a","++","b"` となり、別の結果になります。

### ファイルに保存する

```bash
python3 ProCtokenize.py S247001.c -o S247001.tokens.json
```

`-o` を指定しなければ標準出力です。通常のシェルのリダイレクトも使えますが、`-o` の場合は解析が成功してから出力先を開きます。入力エラーで既存の出力ファイルが空になることを避けられます。入力と出力が同じファイルの場合はエラーにします。

### ハッシュで比較する

```bash
python3 ProCtokenize.py --hash S247001.c
python3 ProCtokenize.py --hash S247002.c
```

同じハッシュなら、正規化した JSON が一致する候補です。必要に応じて JSON そのものも比較してください。ハッシュにはファイル名やパスを含めません。

ハッシュの対象は、通常モードのコンパクト JSON を ASCII で符号化したバイト列です。末尾の出力用改行は含みません。そのため、JSON ファイルに対する `sha256sum` の値とは通常一致しません。

### 読みやすい JSON を出す

```bash
python3 ProCtokenize.py --pretty S247001.c -o S247001.pretty.json
```

トークン列を確認するための、インデント付き JSON です。`--pretty` と `--hash` は併用できません。

### 文字コードを指定する

既定値は `utf-8-sig` で、UTF-8 の BOM あり・なしに対応します。CP932 のソースには明示的に指定します。

```bash
python3 ProCtokenize.py --encoding cp932 S247001.c
```

文字コードの自動推定や、解読できない文字の置換は行いません。日本語の文字列が壊れたまま比較されることを避けるためです。JSON 内の日本語は `\uXXXX` 形式にエスケープしますが、情報は保持されています。`-o` で保存する出力は UTF-8、LF 改行です。

### 標準入力から読む

```bash
cat S247001.c | python3 ProCtokenize.py -
```

標準入力のバイト列も `--encoding` の指定で解読します。

## 複数ファイルを比較する例（Bash / WSL）

カレントディレクトリ以下の `.c` ファイルについて、ハッシュとファイル名の対応表を作ります。ファイル名に空白があっても処理できます。

```bash
while IFS= read -r -d '' file; do
    if hash=$(python3 ProCtokenize.py --hash "$file"); then
        printf '%s\t%s\n' "$hash" "$file"
    else
        printf '解析失敗: %s\n' "$file" >&2
    fi
done < <(find . -type f -name '*.c' -print0) > token-hashes.tsv

sort token-hashes.tsv > token-hashes-sorted.tsv
```

`token-hashes-sorted.tsv` では、同じハッシュのファイルが並びます。エラーになったファイルは表に追加されず、標準エラー出力に通知されます。エラーを空のハッシュとして比較してはいけません。

この一覧の形式は、ファイル名にタブや改行を含まないことを前提とします。比較対象を特定の提出ファイルに限定する場合は、`find` の検索先や条件を調整してください。

既存の `identity_check.sh` が従来版の標準出力をそのまま比較しているなら、呼び出し先を次のように変更する使い方ができます。

```bash
python3 ProCtokenize.py "$file"
```

ただし、終了ステータスが 0 の出力だけを比較してください。従来の最短ソースを前提に文字列を加工している場合は、その部分の見直しが必要です。

## 正規化の規則

| 要素 | 扱い |
| --- | --- |
| 通常のコードの空白・タブ・改行 | トークンの区切りを認識してから除外 |
| `// ...`、`/* ... */` | 文字列・文字定数・ヘッダ名の外側でコメントとして処理 |
| 文字列・文字定数 | エスケープ表記を含めてそのまま保持 |
| 識別子 | 名前をそのまま保持。変数名の変更は吸収しない |
| 数値 | 表記をそのまま保持。`1`、`1.0`、`0x1` は別扱い |
| 演算子・区切り記号 | 最長一致で分割。`++` と `+ +` などを区別 |
| CRLF / CR / LF | LF に統一 |
| バックスラッシュ直後の改行 | コメント認識より前に除去して論理行を作成 |
| プリプロセッサ指令 | 論理行の境界を保持した独立の記録にする |
| 直接指定された `#include` のヘッダ名 | `<stdio.h>` や `"local.h"` を一つの要素として保持 |
| `#define` | 関数形式かオブジェクト形式かを別途保持 |
| ファイル名・パス | 出力に含めない |

プリプロセッサ指令は、論理行の先頭のトークンが `#` または `%:` のときに認識します。例えば、

```c
#define F(x) x + 1
```

は、次の記録になります。

```json
{"pp":["#","define","F","(","x",")","x","+","1"],"macro_kind":"function"}
```

`#define F (x)` は `"macro_kind":"object"` になります。この空白はマクロの種類を変えるため、区別します。コメントを挟んだ `#define F/**/(x)` もオブジェクト形式です。

## 一致・不一致の例

| ソース A | ソース B | 判定 |
| --- | --- | --- |
| `int x = 1;` | `int/**/x=1;` | 一致 |
| `a+b;` | `a + b;` | 一致 |
| `a+ +b;` | `a++b;` | 不一致 |
| `puts("a  b");` | `puts("a b");` | 不一致 |
| `puts("a/*b*/c");` | `puts("ac");` | 不一致 |
| `int x;` | `int y;` | 不一致 |
| `return 1;` | `return 0x1;` | 不一致 |
| `#define F(x) x` | `#define F (x) x` | 不一致 |

## 制限と判定の解釈

### 空白を無視した字句上の比較であり、意味の同一性の判定ではない

特に、マクロの文字列化演算子 `#` は、引数内部の空白の有無を結果の文字列に反映することがあります。

```c
#define STR(x) #x
puts(STR(a+b));
```

と、

```c
#define STR(x) #x
puts(STR(a + b));
```

は、このスクリプトでは一致しますが、出力する文字列は異なります。`__LINE__` など、行番号に依存する処理も、改行を無視した一致から動作の同一性を判断できません。

`#pragma` などの実装依存の指令についても、空白を無視した比較が意味を保存することは保証しません。

### プリプロセッサを実行しない

`#include` のファイルの読込み、マクロ展開、`#if` による分岐選択は行いません。`#if 0` の中も比較対象に含めます。ヘッダの展開で大量の共通コードが混入することを避け、提出された記述を比較するためです。

### 受け付ける記法の範囲

- 通常の識別子、数値の前処理トークン、C の区切り記号、文字列・文字定数と `L` / `u` / `U` / `u8` 接頭辞を字句的に扱います。言語規格ごとの接頭辞の適法性までは検証しません。
- Unicode の識別子や `\uXXXX` / `\UXXXXXXXX` の綴りは扱いますが、両者を同じ名前に正規化したり、識別子の規格上の適法性を完全検証したりはしません。
- ダイグラフはトークンとして扱いますが、`<:` と `[` のような同義表記は統一しません。
- トライグラフに見える並び（`??=` など）は、文字列・コメント内も含めてエラーにします。コンパイラの設定によって解釈が変わるため、推測せず確認を求める仕様です。
- C23 の数字区切り、C++ の raw 文字列、コンパイラ拡張などには対応を保証しません。対象は通常の C 授業課題です。
- 未終了のコメント・リテラル・直接指定ヘッダ名、対応外の文字はエラーにします。ただし、一般の構文エラー・型エラーや不正な数値定数まで検査するものではありません。
- エラーの行番号は、改行を統一し、バックスラッシュによる継続行を結合した後の「論理行」の番号です。

### 重複検知に利用する際の注意

短い課題、配布された雛形、定型的な解法は、独立に作成しても一致することがあります。まず一致候補を絞り、元ソースや課題の自由度と照合してください。配布雛形の自動除外、識別子の置換、部分一致・類似度の算出は実装していません。

## オプション一覧と終了ステータス

```text
python3 ProCtokenize.py [--encoding ENCODING] [--pretty | --hash]
                     [-o OUTPUT] INPUT
```

| 指定 | 内容 |
| --- | --- |
| `INPUT` | 入力ファイル。`-` なら標準入力 |
| `-o OUTPUT` / `--output OUTPUT` | 出力先。省略時は標準出力 |
| `--encoding ENCODING` | 入力文字コード。既定値 `utf-8-sig` |
| `--pretty` | インデント付き JSON |
| `--hash` | 正規化 JSON の SHA-256 |
| `-h` / `--help` | ヘルプ |

終了ステータスは、成功時 `0`、読込み・解読・字句解析・書込みのエラー時 `1`、引数の指定誤り時 `2` です。エラーメッセージは標準エラー出力に出します。

`-o` で既存の出力先を指定した場合、成功時には上書きします。書込み途中の障害に備えた原子的な置換までは行いません。入力ファイル自体は変更しません。

## Python から呼び出す

同じディレクトリに置いて、次のように利用できます。

```python
from pathlib import Path
from ProCtokenize import normalize, canonical_data, LexError

try:
    source = Path("S247001.c").read_text(encoding="utf-8-sig")
    normalized = normalize(source)   # 末尾改行なしのコンパクト JSON
    data = canonical_data(source)    # JSON 化する前の辞書
except (OSError, UnicodeError, LexError) as exc:
    print(exc)
```

比較データには `ProCtokens-v1` という形式識別子を含めています。正規化規則を変更する際は、この識別子も更新し、比較対象全体を再生成する運用を想定しています。
