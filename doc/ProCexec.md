# ProCexec.sh マニュアル

## 目的

`ProCcompile.sh` で生成した Windows 用 `.exe` を一括実行し、ソース・標準出力・標準エラー・終了コードを `exec.log` にまとめる。

`ProCexecStdin.sh` の機能を引き継ぎ、標準入力の有無を `--stdin` オプションで切り替える。

## 必要な環境

- WSL（Debian）、Bash、`realpath` などの標準コマンド。
- Windows 実行ファイルを起動できる WSL の連携機能。
- PDF 化する場合は WSL 側の LibreOffice Writer（`libreoffice` コマンド）。

```bash
sudo apt install libreoffice-writer
```

LibreOffice がなくてもログ作成は実行できる。ソースとプログラム出力は UTF-8 を想定し、文字コード変換は行わない。`nkf` は不要。

## 基本的な使い方

```bash
bash ~/wslbin/ProCexec.sh [--stdin=入力ファイル] [生成物フォルダ]
```

角括弧は省略可能であることを示す。実際のコマンドには入力しない。

| 指定 | 省略時 | 動作 |
| --- | --- | --- |
| `--stdin=ファイル` | 標準入力なし | 指定したファイルを各プログラムの標準入力に渡す |
| 生成物フォルダ | `ProCbuild` | `.c` と `.exe` を探すフォルダ |
| `-h` / `--help` | ― | ヘルプを表示する |

相対パスは、スクリプトの置き場所ではなく、コマンドを実行したカレントディレクトリを基準にする。ログと PDF もカレントディレクトリに保存する。

### 標準入力が不要な課題

```bash
bash ~/wslbin/ProCexec.sh
```

`ProCbuild/` のプログラムを実行する。標準入力には `/dev/null` を渡すため、読み取りは直ちに EOF となる。キーボード入力は渡さず、カレントディレクトリに `input.txt` があっても読み込まない。

### 同じ入力を各プログラムに渡す課題

```bash
bash ~/wslbin/ProCexec.sh --stdin=input.txt
```

各プログラムに、毎回ファイルの先頭から同じ入力を渡す。値の指定を空白で区切る書き方も使える。

```bash
bash ~/wslbin/ProCexec.sh --stdin input.txt
```

旧スクリプトの `bash ProCexecStdin.sh input.txt` は、新スクリプトでは `bash ProCexec.sh --stdin=input.txt` に置き換える。新スクリプトの位置引数は入力ファイルではなく、生成物フォルダ。

### 別の生成物フォルダを指定

```bash
bash ~/wslbin/ProCexec.sh build2
bash ~/wslbin/ProCexec.sh --stdin=input.txt build2
```

空白を含むパスは引用符で囲む。

```bash
bash ~/wslbin/ProCexec.sh --stdin="input data.txt" "build files"
```

オプションとフォルダはどちらを先に指定してもよい。フォルダ名が `-` で始まる場合は、`--` の後に指定する。

```bash
bash ~/wslbin/ProCexec.sh --stdin=input.txt -- -build
```

## 入力ファイルの用意

通常キーボードで入力する内容を、プログラムが期待する順序と区切りで記述する。例えば、数値を１つ読むプログラムなら次のように用意する。

```bash
printf '1.5\n' > input.txt
```

このコマンドは既存の `input.txt` を上書きする。

入力内容は端末入力のようにはエコーされない。ログには入力ファイルの絶対パスを記録するが、入力内容そのものは記録しないため、入力ファイルも一緒に保管する。

## 処理内容と出力

生成物フォルダ直下の `*.c` を順に調べ、同じベース名の `.exe` を実行する。サブフォルダは検索しない。実行時の作業ディレクトリは生成物フォルダであり、プログラム内の相対パスによるファイル操作もそこが基準になる。

| 出力 | 保存先・内容 |
| --- | --- |
| `exec.log` | カレントディレクトリ。標準入力の指定、各ソース、標準出力・標準エラー、終了コード |
| `exec.pdf` | カレントディレクトリ。LibreOffice がある場合にログから変換 |

`exec.log` は入力・フォルダの確認後に空にして作り直す。確認段階でエラーになった場合は、前回のログを残す。画面には実行ファイル名と処理状況を表示する。

対応する `.exe` がない場合は、スキップ理由を記録して次へ進む。`.c` がない `.exe` は実行しない。過去の生成物も対象になるため、課題ごとに作業フォルダを分ける。

LibreOffice がない場合は PDF 化だけを省略する。PDF 変換コマンドの終了コードは確認するが、PDF の更新日時までは検証しないため、必要に応じて更新を確認する。

## 終了コードと注意点

| 終了コード | 意味 |
| --- | --- |
| `0` | 全プログラムが終了コード `0` で終了し、実施した PDF 変換コマンドも成功 |
| `1` | `.exe` がない、プログラムが非ゼロで終了した、または PDF 変換コマンドが失敗 |
| `2` | 引数・入力ファイル・生成物フォルダなどに問題がある |

LibreOffice がなく PDF 化を省略しただけでは、失敗扱いにならない。１件の実行失敗後も残りの提出物を処理する。

タイムアウトは設けていない。無限ループなどで止まらない場合は `Ctrl+C` で中断する。入力が必要なプログラムを `--stdin` なしで実行すると EOF になるため、入力を待つ代わりにエラーになったり、EOF の扱いを誤ったプログラムがループしたりする場合がある。
