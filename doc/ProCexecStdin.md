# ProCexecStdin.sh マニュアル

## 目的

`ProCcompile.sh` で生成した Windows 用 `.exe` に共通の入力ファイルを渡して一括実行し、ソースと実行結果を１つのログにまとめる。

各プログラムには、入力ファイルを毎回先頭から渡す。学生ごとに入力を手で打ち直す必要はない。

## 必要な環境

- WSL（Debian）と Bash、`realpath` などの標準コマンド。
- Windows 実行ファイルを起動できる WSL の連携機能。
- PDF 化する場合は、WSL 側の LibreOffice Writer。

```bash
sudo apt install libreoffice-writer
```

LibreOffice がなくてもログ作成までは実行できる。`nkf` は不要。ソースとプログラム出力は UTF-8 を想定し、文字コードの変換は行わない。

## 実行方法

```bash
bash ~/wslbin/ProCexecStdin.sh [入力ファイル [生成物フォルダ]]
```

角括弧は省略可能な引数を示す記法であり、実際のコマンドには入力しない。

| 引数 | 省略時の値 | 用途 |
| --- | --- | --- |
| 第１引数 | `input.txt` | 各プログラムに渡す標準入力 |
| 第２引数 | `ProCbuild` | `.c` と `.exe` が入ったフォルダ |

相対パスと出力先は、コマンドを実行したカレントディレクトリを基準にする。

```bash
# input.txt と ProCbuild/ がある課題フォルダで実行
bash ~/wslbin/ProCexecStdin.sh

# 入力ファイルだけ変更
bash ~/wslbin/ProCexecStdin.sh input2.txt

# 入力ファイルと生成物フォルダを指定
bash ~/wslbin/ProCexecStdin.sh "input data.txt" "build files"
```

## 入力ファイルの用意

`input.txt` には、通常キーボードで入力する内容を記述する。例えば、数値を１つ読み取るプログラムなら次のように用意する。

```bash
printf '1.5\n' > input.txt
```

複数の値を順に読む場合は、プログラムが期待する順序・区切りで記述する。

```text
1.5
10
```

`>` を使った作成は既存の入力ファイルを上書きする。

スクリプトは入力内容そのものをログに追記しない。また、ファイルから渡した入力は、キーボード入力のようには画面にエコーされない。使用した入力ファイルはログとともに保管する。

## 処理内容

1. 入力ファイルと生成物フォルダを確認する。
2. 生成物フォルダ直下の `*.c` を順に処理する。
3. ソースを `exec.log` に記録する。
4. 同じベース名の `.exe` に入力ファイルを渡して実行する。
5. 標準出力・標準エラー・終了コードを記録する。
6. LibreOffice があれば、ログを PDF に変換する。

各プログラムの実行時の作業ディレクトリは、生成物フォルダである。プログラム内で相対パスを使ってファイルを読み書きするときも、そのフォルダが基準になる。

`.exe` がない提出物は、ソースとスキップ理由を記録して次へ進む。`.c` がない `.exe` は対象にならない。過去の課題の `.c` と `.exe` が残っていれば、それらも対象になるため、課題ごとに生成物を分ける。

## 出力

| 出力 | 保存先・内容 |
| --- | --- |
| `exec.log` | カレントディレクトリ。ソース、実行結果、標準エラー、終了コード |
| `exec.pdf` | カレントディレクトリ。LibreOffice によるログの PDF 変換結果 |

`exec.log` は入力チェックに成功した後で空にし、毎回作り直す。画面には実行ファイル名と処理状況を表示し、プログラムの出力はログへ保存する。

LibreOffice が見つからなければ PDF 化を省略する。PDF 変換コマンドが失敗した場合もログは残る。変換コマンドの終了コードだけを確認しており、新しい PDF の存在・更新までは検証していないため、必要に応じて `exec.pdf` の更新日時を確認する。

## 終了コード

| 終了コード | 意味 |
| --- | --- |
| `0` | 対象プログラムがすべて終了コード `0` で終了し、実施した PDF 変換コマンドも成功 |
| `1` | 実行ファイルがない、プログラムが非ゼロで終了した、または PDF 変換コマンドが失敗 |
| `2` | 引数、入力ファイル、生成物フォルダなどに問題がある |

LibreOffice がなく PDF 化を省略しただけでは、失敗扱いにならない。プログラムが非ゼロで終了しても、残りの処理を続ける。予期しないファイル操作の失敗では、途中停止する場合がある。

## 実行が止まらない場合

タイムアウト機能はない。提出プログラムが無限ループになった場合などは、`Ctrl+C` で中断する。入力ファイルの末尾に達すると標準入力は EOF となり、追加の手入力を待つ状態にはならない。ただし、EOF の処理を誤ったプログラムはループすることがある。
